Provider API keys

separate credentials, unchanged default

Store keys for several providers. Credentials are write-only; status describes local declarations, not a successful paid request.

Default provider: anthropicChange it separately in Configuration

  • AnthropicDefaultSet in deployment
    ANTHROPIC_API_KEY

    Present in .env; presence does not verify that a key works.

  • OpenAISet in deployment
    OPENAI_API_KEY

    Available for jobs that select OpenAI; the default stays Anthropic.

  • Google GeminiNot set
    GEMINI_API_KEY

    Add a separate key without changing either existing provider.

Add or replace a provider key

Only the selected provider slot changes. The default provider stays the same. A running worker needs a separate restart.

Subscription authentication

host-owned credentials, safe status only

Subscription credentials stay on the owning host. Use its supported sign-in flow, separately from API keys.

Sign in with ChatGPT on the owning host
Host connection guideOfficial provider guidance
  1. Configure an openai-chatgpt connection and explicit openai binding in the reviewed policy.
  2. Complete authorization on the owning host. Follow its loopback callback and tunnel instructions.

The console never receives OAuth credentials.

Claude subscription and community compatibility
Host connection guideOfficial provider guidance
  1. Read the vendor's authentication restrictions before selecting a community route.
  2. Reviewed, pinned community adapters use their own host sign-in and refresh flow.
  3. Official claude setup-token is for Claude Code. It is not an API key to paste here.

Community compatibility is not vendor endorsement.
